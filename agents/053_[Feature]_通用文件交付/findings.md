# 发现

- 现有整文件 read/write 会将完整内容载入内存，不适合持续大文件交付；新能力采用流式传输。
- 上传使用固定 8 MiB 分片和独立签名，以适应服务端单请求大小限制。
- 新增能力通过握手 capabilities 声明；只有具备对应能力的客户端接收新任务。
- 目录移动与清理需要目录内标记的 hash，且必须拒绝危险链接、保留当前会话和其他本机内容。
- 本机缺少 MSVC C 头文件，Windows 交叉编译尚未到达连接器 Rust 检查；此检查不能作为 Windows 已验证证据。
- 移动需在 Windows 使用不带覆盖标志的 MoveFileExW；清理路径的权限错误不能当作目标缺失；清单递归同时限制总 entries，避免目录中大量目录耗尽资源。
- 客户端版本元数据统一升至 2.2.6；发布及真实传输/撤销验证仍由主 agent 后续处理。
