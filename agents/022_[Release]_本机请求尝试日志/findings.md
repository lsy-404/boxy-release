- 现有 result 只含最终聚合结果；自动刷新、重试和图片补全中间 HTTP 调用不回传，服务器无法事后恢复实际 endpoint/status/body。
- 限定本次任务为实际尝试记录和原始回执留档，不更改认证签名协议或自动重放旧任务。
- 服务端会先交付加密 journal，旧客户端收到/下发的任务也可归档；实际 HTTP 尝试需要新版上报，不能假设旧客户端具备此字段。
- 合并实现通过 39+6+6 Rust 回归；独立复查确认字段、实际尝试位置及失败路径一致。fmt与打包测试通过。
- 极端2MiB NUL主响应会序列化为14–15MB，该输入在旧1.4MB服务端限制下也从不合法；本次服务端明确8MiB有界限制覆盖旧合法回执与常见新元数据，不为极端控制字符输入扩大到可能耗尽Worker内存的体积。
