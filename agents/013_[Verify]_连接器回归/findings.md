# Findings

- The public source starts at 49780c8 (v2.0.3). Historical v1 reference is private repo commit 7f9a594; all historical inspection was read-only.
- Existing v2 transport already implements continuous session snapshots, signed writeback receipts, Dreamtonics actions, product fetch/delete/inspection, folder and SV2 controls, translations/logo metadata, and platform process blocking. The user-approved v2 split keeps decrypted/offline session edits and authentication state in the cloud Worker rather than the local client.
- V1 included a local session-file selector and default-path reset. The v2 setup UI accepted only `--session` or the default path, so ordinary users could not select another session. Added a native file picker and default reset before connection; the chosen path is captured by the connection closure and cannot change during the operation.
- `--session` remains the initial editable path, while the reset control is tied to `session_io::default_session_path()`. Connect validates that the submitted path is nonempty and points to an existing file before starting; the selected path is then held for the operation.
- V1 `send_quick_request("login")` derived `device_id` from the decrypted local session. The v2 `DirectoryTask` now accepts the Worker-provided `deviceId` and uses it in the legacy request payload, with the original local computer-name fallback.
- V1 custom requests accepted valid HTTPS endpoints on any host and port up to 2048 characters. The v2 connector preserves unrestricted host/port behavior while requiring no userinfo or fragment, and retains bounded method/body/response handling, the timeout, and disabled redirects. Product file downloads remain Dreamtonics-host restricted.
- V1 session inspection, offline-license toggling/cache writes, and local token-refresh commands operated on plaintext session documents. The v2 public client receives encrypted session data and delegates edits to the Worker; implementing these old local commands here would cross the current client/Worker boundary and was not attempted.
- `cargo` default stable resolves to rustc 1.92.0, below locked `sysinfo` 0.39.6's rustc 1.95 minimum. Installed Rust 1.98.0 works; no dependency versions were changed.
- Regression coverage keeps conflict and validation negative controls intact and uses a local HTTP fixture to validate the Ed25519 signature, snapshot URL, ciphertext and source hash, and writeback-pending response.
- The configured 1Password SSH signing key file was unavailable when committing. The commit succeeded with signing disabled for that one command only; no Git configuration was changed.
- V1 requested product logos by keys, matched the local `databases/meta/*.json` identity and recursively located image/icon/logo/profile URLs, then fetched fixed `/my_licenses` data for unmatched keys. Restored this as the local `product_logos` action after the existing expected-session hash check; the encrypted session stays untouched and the Worker remains the editor of session state.
- Logo fetches use the connector's fixed licenses HTTP helper (2 MiB response cap), request local metadata images before licenses fallback, and skip the licenses request when local metadata covers all requested keys. Image URLs are bounded to 2048 characters and HTTPS Dreamtonics domains; redirects are disabled, image reads are capped at 512 KiB per image and aggregate, and only PNG/JPEG/GIF/WebP signatures are accepted.
- Remote logo caches accept only 1-128 ASCII alphanumeric, dash, or underscore IDs and use `create_new` to avoid replacing existing files. Cached logo reads now recognize all four supported image formats. The serialized response is capped at 512 KiB.
- Root `/test` regression fixtures mock both the licenses response and image downloader to test identity matching, fallback, skipping unnecessary network access, trust/signature/size bounds, and supported-format cache readback without contacting Dreamtonics.
