# Findings

- [Observed] Directory task execution calls `complete_task` after computing each result. `complete_task` sends once through `post_signed_json`; task execution itself is outside the transport helper, so a receipt-only retry can avoid rerunning local actions.
- [Observed] `post_signed_json` serializes into `Zeroizing<Vec<u8>>` but creates one nonce/signature and delegates status/body handling to `parse_response`. A receipt retry needs a fresh signature per attempt while keeping the serialized bytes identical and zeroized.
- [Observed] Existing poll retry policy retries temporary transport/read failures and selected temporary HTTP statuses; auth and other client errors return immediately. Cancellation is checked between retries using `wait_or_stop`.
- [Confirmed by parent] The service is implementing authenticated replay of the same receipt body, returning a completed ACK without rerunning side effects. Conflicting bodies return 409 and auth/unknown receipt returns 404. Client retries will occur only for transport or response-read ambiguity; HTTP statuses terminate immediately.
- [Design] Directory tasks already receive `ConnectorHost`; pass it only to a dedicated directory receipt helper so cancellation is checked during bounded backoff. Command receipts and unrelated POSTs remain single-shot.
- [Verified] Local TCP fixtures accepted a complete request then truncated the 200 ACK; the client resent identical body bytes with a fresh valid signature. Auth rejection returned after one request, repeated dropped connections stopped after six attempts, cancellation interrupted the backoff, and an end-to-end connected run sent two receipt attempts for one delivered task.
